# Saza Event Portal (Клиентски портал и работно пространство за агенция)

Професионална мултитенантна система за управление на събития, сватби и корпоративни тържества, разработена стриктно по **Спецификация за агент за събития (Event Portal Agent Spec BG)**.

Системата предоставя споделено работно пространство за агенцията и прозрачен, модерен клиентски портал с пълна изолация на данните, криптографска одитна следа, стриктна финансова отчетност и гаранция за нулево изтичане на вътрешна информация.

---

## 🚀 Бърз старт и команди

### 1. Изисквания
- **Node.js**: v20+ (препоръчително Node.js v24 с вградена поддръжка за TypeScript)
- Без задължителни външни бази за локално тестване — използва вградената транзакционна база с пълен ACID контрол, както и пълни PostgreSQL/Supabase миграции за продукция.

### 2. Инсталация и конфигурация
```bash
# Копиране на конфигурационния шаблон
cp .env.example .env
```

### 3. Генериране на синтетични данни (Seed)
Генерира пълна база с две организации (Орг А и Орг Б), 4 събития, 7 тестови акаунта, публикувани/непубликувани етапи, версии на оферти, одитни записи и плащания към контролирано време `2026-10-12T10:00:00.000Z`:
```bash
npm run seed
```

### 4. Изпълнение на тестовия пакет (Всички 40 теста T01–T40 + HTTP API тестове)
```bash
npm test
# или поотделно:
npm run test:t01-t40   # 40-те теста от матрицата на спецификацията
npm run test:http      # Интеграционни тестове на REST API & Storage
```
> **Резултат**: 40/40 теста преминават успешно (100% PASS). Подробен отчет се намира в [TEST_REPORT.md](file:///Users/sando/Desktop/Saza%20Event%20Portal/TEST_REPORT.md).

### 5. Стартиране на HTTP Сървъра (REST API + Клиентски портал)
Системата включва пълен вграден Node.js HTTP сървър без външни рамки (Express/Fastify):
```bash
# Режим на разработка (с автоматично наблюдение на файловете):
npm run dev

# Продукционен режим:
npm start
```
Сървърът слуша на `http://localhost:3000` и обслужва:
- **Уеб интерфейс**: `http://localhost:3000` (WCAG 2.2 AA съвместим)
- **REST API**: `http://localhost:3000/api/...`
- **Проверка на състоянието**: `http://localhost:3000/api/health` и `/api/status`

### 6. Стартиране на фоновия Outbox Worker за имейли
```bash
# Непрекъснат фонов процес (изпраща имейли на всеки 5 секунди):
npm run worker

# Еднократно изпълнение на чакащите съобщения:
npm run worker:once
```

## 🎭 Ролеви селектор за интерактивна демонстрация

В най-горната лента (`Demo Bar`) на приложението е наличен ролеви селектор с 7-те ключови профила от спецификацията:
1. 👰 **Елена (Клиент А - Сватба, Decision Maker)**:
   - Пълен достъп до своето събитие
   - Отговаря на 4-те ключови въпроса в „Обзор“
   - Право да одобрява или отхвърля варианти на предложения и бюджети
   - Достъп до финансови документи и график на плащанията
2. 👁️ **Виктория (Клиент Viewer - без право на бюджет)**:
   - Вижда статуса и плана на сватбата
   - Стриктно **скрити** финансови графики, суми и файлове (`can_view_budget = false`)
   - Бутонът за вземане на решение е деактивиран (само за преглед)
3. 🏢 **Борис (Клиент Б - Корпоративно събитие)**:
   - Достъп само до корпоративното парти
   - Пълна изолация от данните за сватбата на Елена
4. 📋 **Константин (Координатор, Орг А)**:
   - Достъп до Agency Workspace
   - Управление на етапи (чернови и публикуване)
   - Потвърждаване на актуалност на данните
   - Виждане на вътрешни бележки и доставчици
5. 👔 **Мария (Manager, Орг А)**:
   - Управление на събития, бюджети и координатори
6. 👑 **Александър (Owner, Орг А)**:
   - Пълен административен контрол, отнемане на достъп и одитни логове
7. 🏢 **Георги (Организация Б - Изолация)**:
   - Демонстрация на строга изолация между организациите (T04 & T08)
   - Опитът за достъп до събитие на Орг А връща `404 Not Found` без да издава съществуването му

## 🔒 Ключови принципи на сигурност и финанси

1. **Мултитенантна изолация**:
   - Всички таблици имат `organization_id` и `event_id`.
   - Заявка към ресурс от друга организация връща `404 Not Found`, а не `403 Forbidden`, за да се предотврати сканиране на съществуващи идентификатори.
2. **Нулево изтичане на вътрешни данни (Leaking Prevention)**:
   - Клиентските DTO обекти стриктно филтрират `internal_notes`, `supplier_cost_cents`, `margin_cents`, `supplier_id` и чернови на етапи.
3. **Финансова цялост**:
   - Всички суми се съхраняват в целочислени евроцентове (`integer cents`). Float аритметика е забранена.
   - Плащанията и сторно записите се извършват с насрещни коригиращи записи с пълна ревизионна следа.
4. **Криптографски хеширани решения**:
   - Всяко одобрение на клиент съхранява SHA-256 хеш на точната версия на предложението и прилежащите файлове.
   - Използва се транзакционен механизъм с `idempotency_key` за защита от мрежови повторения.
5. **Транзакционен Outbox модел**:
   - Известията се записват в `notification_outbox` в същата база данни транзакция, в която настъпва бизнес събитието, гарантирайки надеждна доставка при срив на външни пощенски сървъри.
